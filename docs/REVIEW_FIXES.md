# Review fixes and rollout

This change fixes the eight findings from the review of `cc1595a6` and reconciles
them with the newer base-branch security fixes.

- Sellers cannot transition a rejected or pending listing to active, draft or sold.
- Independent inspection is controlled by the server. Seller create/edit requests
  cannot award or remove the badge. The temporary admin toggle from the newer base
  is not shipped as a general approval service; any already logged admin approval
  is preserved by migration 0013.
- Admin password failures no longer lock out all administrators. Atomic source
  quotas apply on Vercel using its trusted IP header; OTP delivery quotas are only
  spent after a correct password. On another host, configure equivalent trusted
  reverse-proxy rate limiting before exposing admin authentication.
- Both OTP flows lock the latest challenge while checking and consuming it. User
  OTP issuance also uses an atomic DB quota, so concurrent requests cannot bypass
  the five-codes-per-hour limit.
- Price range, confidence and sample count are saved together. Legacy estimates
  without that evidence remain explicitly weak until recalculated on listing edit.
- Search, facets, public scores and admin listings use the current seller and
  Morocco calendar date. `listing_trust_score` mirrors `trustScore`, with PostgreSQL
  parity regression tests. The stored `trust_score` column is now only a snapshot.
- Chat polling owns a cursor per conversation. Send acknowledgements do not advance
  it; duplicate messages and late responses from another conversation are ignored.
- Seller forms collect an actual optional technical-control expiry date. Dates
  are validated and a control remains valid through its stated expiry day.
- The newer base fixes for profile phone preservation and the admin-only Blob
  storage self-test are retained.

## Deployment

Apply `db/migrations/0013_review_security_trust.sql` with the existing
`npm run db:migrate` command before serving this code. Coordinate the migration
and application release while seller writes are paused, so the old endpoints
cannot add new self-certified inspection flags or generated control dates during
the changeover.

The migration archives prior seller inspection claims in
`seller_inspection_claimed`, clears unverified independent-inspection flags, and
restores only a latest `listing:inspect` action that was already recorded in
`admin_log`. It archives both the original fixed technical-control sentinel dates
and the relative +12-month/-1-month dates generated by base commit `df9c62a`
before the real expiry-date field is served. Sellers can then enter the actual
expiry date through the edit form.

The migration also adds `auth_rate_limits` and `fair_price_meta` and creates the
live score function. Keep this additive schema when reverting the application;
restoring the old endpoints would restore the reviewed vulnerabilities.

Live trust scoring trades use of the old score index for immediate correctness
after verification changes and date rollovers. Check query latency on production
volumes before introducing any future caching; cached scores must be invalidated
for seller verification, listing/history edits and calendar changes.

## Validation

Run `npm test`, `npm run typecheck`, `npm run lint` and `npm run build`.
Tests use isolated PGlite PostgreSQL engines, including the real migrations,
queries and seller endpoints. The pool adapter serializes transaction ownership;
these tests do not replace load/concurrency testing against production PostgreSQL.
No production credentials, database, email or Blob storage are used by the tests.

ESLint now runs via its CLI. React Compiler diagnostics are introduced as warnings
for the existing application; hook-order and other recommended correctness rules
remain errors. Existing warnings are not silently disabled.
